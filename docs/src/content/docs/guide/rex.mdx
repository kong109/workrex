description: Use Rex as an alternative multiplexer backend

:::caution[Experimental]
The Rex backend is new. It supports window mode. Session mode is not supported yet.
:::

Rex can be used as an alternative to tmux. workmux detects it automatically from `$REX_BLOCK`, which Rex sets in every pane. To force it, set `WORKMUX_BACKEND=rex`.

If you run tmux, WezTerm, Zellij or kitty inside a Rex pane, workmux uses that multiplexer. Rex is checked last, because every program started from a Rex pane inherits `$REX_BLOCK`.

workmux needs a Rex server that speaks API revision 8 or 9. On first use it reads the server's `server.version` and stops with `unsupported Rex <version>` when the server's supported revisions miss that range.

## Differences from tmux

| Feature              | tmux                 | Rex                                 |
| -------------------- | -------------------- | ----------------------------------- |
| Agent status in tabs | Yes (window names)   | Dashboard only                      |
| Tab ordering         | Insert after current | Insert after current                |
| Scope                | tmux session         | Rex session                         |
| Pane IDs             | `%12`                | `block:<uuid>`                      |
| Prompt delivery      | Paste buffer         | Paste event (bracketed when needed) |
| Respawning a pane    | Same pane ID         | New block in the same place         |
| Session mode         | Yes                  | Not yet                             |
| View follows `add`   | Caller's session     | No                                  |

- **Tabs.** A workmux window is a Rex window, labeled with the window name. New windows open right after the current one.
- **Panes.** Each pane is a Rex block. Splits keep the configured `size` or `percentage`.
- **Respawning.** Rex cannot restart the program in a block. When workmux needs to restart a pane, it opens a new block in the same place and closes the old one, so the pane ID changes.
- **Capture.** `workmux capture` reads the block's full scrollback and keeps the last lines.
- **The app.** Rex.app keeps its own shown tab, apart from the window the Rex session makes active. Rex does not report which session an app shows now, so `add` and `open` never move the app: the new window becomes the session's active window, and the app keeps showing what it showed. You open the new tab in the app yourself. tmux instead moves every client that shows the caller's session.
- **Jumps.** The dashboard, the sidebar, `last-agent` and `last-done` do move the app. They ask the Rex.app client that owns your pane, which is the app that last showed it, to show the target.
- **Shells.** workmux starts each block's shell directly as a login shell (`$SHELL -l`), as tmux does. It does not go through `/usr/bin/login`, so the environment of the Rex server reaches the pane unchanged.

## Remote Control

A jump needs Remote Control, which you turn on in Rex Settings. Without it, the app refuses the jump and the target is not focused. The dashboard and the sidebar stay open and print nothing to the terminal; the [dashboard layer](#dashboard) shows a hint in its footer instead. `last-agent` and `last-done` print `Rex.app did not switch: Remote Control is off. Turn it on in Rex Settings so workmux can switch the app.` once.

## Dashboard

The [dashboard](/guide/dashboard/) opens in a floating layer over the current tab, the Rex counterpart of a tmux popup. Copy [`resources/rex/workrex.lua`](https://github.com/kong109/workrex/blob/main/resources/rex/workrex.lua) to `~/.config/rex/workrex.lua` and load it from `~/.config/rex/init.lua`:

```lua
require("workrex")
```

Check the file and reload the configuration:

```bash
rex config check ~/.config/rex/workrex.lua
rex config reload
```

Press `Shift+Cmd+D`, or run **workrex: Open Dashboard** from the command palette. Pressing the key again while the dashboard is open focuses it instead of opening a second one. The key replaces Rex's default for **Split Pane Down**, which keeps `Shift+Cmd+Down`. To use another key, change the `rex.bind` line at the end of the file.

- **Jumping.** Choosing an agent switches the app to the agent's tab, focuses its block, and closes the layer. With [Remote Control](#remote-control) off, you can still jump to an agent in the tab the dashboard is open over. Choosing an agent in any other tab or session keeps the dashboard open with `Turn on Remote Control in Rex Settings to jump across tabs` in its footer until you press a key. If the app does not answer within 1 s, the block is focused and the layer closes, since the app may still switch late.
- **Closing.** Press `q` to close the layer. Focus returns to the block you were in.
- **Options.** The action passes `args` to `workrex dashboard`, for example `rex.bind("shift+cmd+d", "workrex_dashboard", { args = { "--session" } })`.
- **Binary.** The action runs `workrex` from your login shell's `PATH`. To run another binary, set `WORKREX_BIN` in the Rex server's environment.

## Requirements

- The `rex` CLI. Inside a Rex pane it is already on `PATH`.
- macOS or another Unix-like OS (named pipes for handshakes)

## Choosing the server

workmux talks to the server named by `REX_SERVER`. When `REX_SERVER` is unset, it uses the server the `rex` CLI finds by default, and asks it for its address with `rex whoami`.

workmux never starts a Rex server and never stops one. Every call passes `--autostart=false`.

:::note
If you run a second Rex server on its own socket, set `REX_SERVER` in that server's environment before starting it. Rex panes inherit the server's environment, and without `REX_SERVER` the `rex` CLI in those panes reaches the default server instead.
:::

## Agent state across restarts

workmux identifies the server by its address, which stays the same across restarts, and detects a restart from the server instance ID that `rex whoami` reports. After a restart, `workmux resurrect` reopens the agent windows that were running.

## Known limitations

- Session mode (`--session` or `mode: session`) is not supported yet
- `add` and `open` do not move Rex.app to the new window
- Agent status icons do not appear in tab titles
- Remote agents need tmux
