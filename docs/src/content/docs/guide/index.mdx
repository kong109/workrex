workrex runs AI coding agents in parallel. Each task gets its own
[git worktree](https://git-scm.com/docs/git-worktree), its own branch, and its
own session in [Rex](https://www.superlogical.com/rex/docs/), with the agent
already started. Agents never share a working directory, so one agent's edits
and builds never get in another agent's way. When a task is done,
`workrex merge` merges the branch and removes the worktree, the Rex session,
and the local branch.

workrex is a fork of [workmux](https://github.com/raine/workmux) by Raine Virta.
The fork adds a Rex backend and installs as its own binary, `workrex`, so it can
run next to an upstream `workmux` install. It reads the same configuration
files as workmux. The rest of workmux works the same way, including tmux,
WezTerm, kitty, and Zellij support.
[NOTICE.md](https://github.com/kong109/workrex/blob/main/NOTICE.md) lists what
the fork renames.

## A task from start to finish

Run these commands from a Rex pane inside your project's repository:

```bash
# Start an agent in a new worktree and Rex session
workrex add user-auth -p "Add password reset"

# Watch every agent; Enter jumps to its session
workrex dashboard

# Merge, then remove the worktree, session, and branch
workrex merge user-auth
```

Without workrex, the same task takes a `git worktree add`, a copy of your
`.env`, a dependency install, a new session with the right panes, and the agent
command typed by hand. Cleanup takes several more commands. workrex runs those
steps from your [configuration](/guide/configuration/).

## How workrex uses Rex

workrex detects Rex from the `$REX_BLOCK` variable that Rex sets in every pane.
It needs no extra setup.

- **One session per task.** Each worktree gets its own Rex session. To get one
  tab per task in the current session instead, set `mode: window`.
- **Rex.app stays where it is.** `workrex add` can run from a background agent's
  pane, so it never switches the app. It prints how to open the new session.
- **Status without hooks.** Agents that report Rex program status, such as
  Claude Code, show whether they are working, waiting, or done.
- **A floating dashboard.** With the bundled Lua file loaded, a key opens the
  [dashboard](/guide/dashboard/) as a layer over the current tab.

The [Rex guide](/guide/rex/) covers each of these, and the differences from
tmux.

## What else workrex does

- Copies or symlinks files such as `.env` and `node_modules` into new worktrees,
  and runs setup commands after creation. See
  [Configuration](/guide/configuration/).
- Lets an agent hand tasks to new worktrees with the
  [`/worktree` skill](/guide/skills/#worktree).
- Names branches from your prompt with
  [`--auto-name`](/reference/commands/add/#automatic-branch-name-generation).
- Runs agents in [containers or VMs](/guide/sandbox/), or on
  [remote servers](/guide/remote/) over SSH.
- Sends prompts to running agents and waits on them from scripts, with `send`,
  `capture`, and `wait`. See the [command reference](/reference/commands/).

## Why git worktrees

A git worktree is a second checkout of the same repository, on its own branch,
in its own directory. Switching tasks is a `cd`, with no stash and no
temporary commit. Two worktrees can build, install dependencies, and run tests
at the same time without touching each other's files. That isolation lets
several agents work on one repository at once.

## Requirements

- macOS on Apple Silicon or Linux on x86_64 for the prebuilt binaries. Other
  platforms can [build from source](/guide/installation/#build-from-source).
- Git 2.5 or later.
- Rex, with a server that speaks API revision 8 or 9. workrex also works with
  tmux, [WezTerm](/guide/wezterm/), [kitty](/guide/kitty/), or
  [Zellij](/guide/zellij/).

To get started, [install workrex](/guide/installation/), then follow the
[quick start](/guide/quick-start/).
